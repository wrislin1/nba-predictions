# Play-by-Play Archive (1996-97 → 2025-26) — Design

*Approved 2026-07-31. Brainstormed after verifying that stats.nba.com is
reachable again (the 2026-07-29 TLS failure was local AdGuard filtering, not
server-side blocking) and that `PlayByPlayV3` returns full event logs back to
the 1996-97 season while `PlayByPlayV2` now returns empty JSON for everyone.*

## Goal

Acquire and preserve the complete NBA event-level play-by-play history —
every regular-season, playoff, and play-in game from 1996-97 through 2025-26
(~38,500 games, ~18M events) — as a validated, season-partitioned Parquet
dataset, using the repository's existing cache/validation conventions.

## Purposes

1. **COVID HCA analysis depth** — foul calls by period and clutch time,
   scoring runs, and timeout patterns with and without crowds (Slice 3
   enrichment).
2. **Model features** — pace, clutch performance, garbage-time-adjusted
   statistics for future prediction work.
3. **Complete archive** — durable preservation of the full event history
   while the source is accessible.

## Decisions made during brainstorming

| Decision | Choice |
|---|---|
| Source | `nba_api` `PlayByPlayV3` exclusively (canonical schema, full 1996+ coverage); no hoopR/ESPN hybrid |
| Game types | Regular season + playoffs + play-in; no preseason or All-Star |
| Storage | `data/parquet-large/pbp/` season-partitioned Parquet, **gitignored**, mirrored to NAS; raw JSON cache gitignored and NAS-mirrored |
| Repo policy | The <100 MB fresh-clone criterion is preserved; only code, tests, and audit reports are committed |
| Sequencing | Own design (this document) + a separate implementation plan, following the playoff-game-results pattern; fetch starts after plan approval |
| Derived features | Regenerated by code in later work, never stored in the archive |

## Constraints

- **Politeness:** ~1.5 s spacing between stats.nba.com requests, bounded
  exponential backoff, `nba_api` default browser-like headers. Total bulk
  fetch is roughly 20–26 hours of unattended wall-clock and is fully
  resumable; cached games are never re-fetched.
- **AdGuard preflight:** reuse the `preflight_dns()` sinkhole check from
  `stats_nba.py` before any fetch batch.
- **Disk:** raw JSON cache is an estimated 8–15 GB and lives under the
  repository's gitignored `data/raw/` on `/home`; both raw cache and Parquet
  output are mirrored to `/mnt/nas/llm` as the durable archive copy.
- **No dependency on the `playoff-game-results` branch merging first** — the
  worklist is built independently (below) and cross-validated where master's
  tables already have coverage.

## Worklist construction

The fetch worklist comes from `LeagueGameFinder`, one request per season per
season type (Regular Season, Playoffs, PlayIn), cached like all other raw
responses.

Cross-validation before fetching:

- Regular-season IDs for 1997+ must exactly match the `game_id` set in
  `data/parquet/games.parquet` (which already carries canonical stats.nba IDs
  back to 1984, all with the `002` regular-season prefix).
- Playoff ID counts per season must fall within known series bounds
  (15 series × 4–7 games; play-in fixed structure from 2020-21 onward).
- Game-type classification is derived from the ID prefix
  (`002` regular, `004` playoff, `005` play-in) and must agree with the
  season-type request that returned the ID.

Any mismatch stops the run with a diagnostic report; it is not skipped.

## Fetcher (`src/nba_data/pbp.py`)

Same conventions as `stats_nba.py`:

- raw JSON response and request metadata cached per game under
  `data/raw/stats_nba/pbp/<season>/<game_id>.json` **before** any parsing;
- bounded exponential backoff with a hard stop (not a silent skip) after
  repeated failures for the same game;
- resumable: a run enumerates the worklist, skips games with a valid cached
  response, and fetches the remainder;
- `python -m nba_data pbp --season 2025-26` supports incremental refresh of a
  season in progress; the default target is the full worklist.

## Table (`data/parquet-large/pbp/season=YYYY/*.parquet`)

Season-partitioned, gitignored, NAS-mirrored. One row per event. Schema is
the flattened `PlayByPlayV3` action record:

| Column | Notes |
|---|---|
| `game_id`, `action_number` | primary key |
| `season`, `game_type` | partition + `regular`/`playoff`/`playin` from ID prefix |
| `period` | 1–4, 5+ for overtimes |
| `clock` | original V3 string, e.g. `PT11M35.00S` |
| `clock_seconds` | parsed seconds remaining in period, added beside the source string |
| `team_id`, `team_tricode` | nullable (neutral events) |
| `person_id`, `player_name` | nullable |
| `action_type`, `sub_type` | V3 vocabulary preserved verbatim |
| `shot_result`, `is_field_goal`, `shot_value`, `shot_distance`, `x_legacy`, `y_legacy` | shot detail where applicable |
| `score_home`, `score_away` | running score |
| `description` | source text preserved verbatim |

Original V3 field values are preserved; parsed fields are added beside, never
replacing, source strings — the same principle as the leaders parser.

## Validation gates (build fails loudly)

1. Every worklist game has a cached response containing at least one event.
2. Per-game event count within sane bounds (~300–1,000).
3. The final event's `score_home`/`score_away` matches the game's scores in
   `games.parquet` (strongest available cross-source check; applies to games
   present in master's tables).
4. Periods are contiguous from 1 with no gaps.
5. No duplicate `(game_id, action_number)` pairs.
6. A per-season coverage report (games fetched, events, gate results) is
   committed to `docs/audits/`.

Early-era caveat: 1996–2000 seasons are known to be thinner on event detail
(fewer event types, occasional missing descriptions). Gates 1–5 still apply;
the coverage report documents per-season event-type availability rather than
gating on it.

## Tests (pytest, fixture JSONs)

- Clock parsing: `PT11M35.00S`, sub-minute values (`PT00M07.30S`), zero.
- Score-continuity gate fires on seeded bad input.
- Worklist cross-validation fires on a mismatched regular-season ID set.
- Game-type classification from ID prefix, including rejection of unknown
  prefixes.

## Out of scope

- Derived features (pace, clutch splits, foul-timing measures for the HCA
  analysis) — regenerated by code in later work, never stored.
- Pre-1996 play-by-play (does not exist at the source), preseason, All-Star.
- Live/in-progress game ingestion.
- Any committed Parquet: the repository gains only code, tests, and audit
  reports from this workstream.

## Success criteria

1. Every game in the worklist (~38.5k) has a cached raw response and rows in
   the Parquet dataset; validation gates 1–5 are green for every season.
2. Regular-season coverage for 1997+ exactly matches `games.parquet`;
   playoff/play-in coverage matches the season-type worklists.
3. Raw cache and Parquet dataset are checksummed and mirrored to NAS; the
   fresh-clone size criterion of the main design is unaffected.
4. The per-season coverage report exists in `docs/audits/` and documents
   early-era event-type availability.
