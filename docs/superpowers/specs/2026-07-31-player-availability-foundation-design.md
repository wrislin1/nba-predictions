# Player Availability & Workload Foundation (1984–2026) — Design

*Approved 2026-07-31. Brainstormed from the question: how can the project
explore back-to-back games, resting players, and schedule-driven injury
effects around the COVID seasons, and what data is missing? The answer was a
decomposition: three analyses (rest → performance, schedule compression →
injuries, load-management trends) sharing one data foundation. This document
designs that foundation; each analysis gets its own later spec.*

## Goal

Give any analysis in this repository the ability to answer *who played, how
much, who was absent, and why*, for ending seasons 1984–2026 (regular season,
playoffs, and play-in), by adding:

- **D1 — `player_games`**: one row per player-appearance per game, from
  stats.nba.com bulk game logs (~1.2M rows).
- **D2 — `injury_events`**: injury, injured/inactive-list, and
  personal-reason events from Pro Sports Transactions.
- **D3 — schedule features**: rest, density, and travel features derived by
  code from `games.parquet`, plus one small committed location reference.

## Decisions made during brainstorming

| Decision | Choice |
|---|---|
| Scope | Data foundation only; the three analyses are separate future specs |
| Era | Ending seasons 1984–2026, matching the modern `games`/`team_games` publication boundary |
| Player-game source | Bulk `LeagueGameLog` (player mode) via `nba_api` — a few requests per season, not per-game box scores |
| Injury source | Pro Sports Transactions (Injuries, Injured/Inactive List, Personal categories); official NBA injury-report PDFs (2019+) deferred as future enrichment; pre-compiled third-party dumps rejected for provenance |
| Storage | `data/parquet-large/` gitignored + NAS-mirrored (PBP-archive precedent); only code, tests, manifests, and audit reports are committed |
| Derived features | Regenerated by code, never stored |

## Constraints

- **Politeness.** stats.nba.com: `nba_api` defaults, ~1.5 s spacing,
  `preflight_dns()` AdGuard sinkhole check, bounded backoff with hard stop.
  prosportstransactions.com: b-ref discipline — ≤1 request per 12 s, browser
  UA, ordinary TLS, no parallel requests, hard stop on HTTP/rate-limit/block
  page/schema drift; site terms and robots are checked before implementation,
  the same way the Sports Reference policies were recorded.
- **Cache-first.** Every raw response (JSON or HTML) is cached with a
  SHA-256 metadata sidecar before any parsing; fetches are resumable and
  cached items are never re-fetched.
- **Fetch cost.** Player logs: ~130 requests (one per season per season
  type) — minutes to hours. PST: a few thousand paginated result pages —
  roughly one 8–12 hour polite unattended, resumable fetch.
- **Repo policy.** The <100 MB fresh-clone criterion is preserved. Raw
  caches and Parquet outputs are mirrored to `/mnt/nas/llm` as durable
  copies.

## D1 — `player_games` (`data/parquet-large/player_games/season=YYYY/`)

### Fetcher (`src/nba_data/player_logs.py`)

Bulk `LeagueGameLog` in player mode, one request per season per season type
(Regular Season, Playoffs, PlayIn), cached under
`data/raw/stats_nba/player_logs/`. Same conventions as `stats_nba.py`.
CLI: `python -m nba_data fetch-player-logs [--season YYYY]`; incremental
refresh of a season in progress is supported.

### Table

One row per player-appearance per game. Original source values are
preserved verbatim; parsed/derived fields sit beside them (leaders-parser
principle).

| Column | Notes |
|---|---|
| `game_id`, `person_id` | primary key |
| `season`, `game_type` | ending season; `regular`/`playoff`/`playin` from ID prefix (`002`/`004`/`005`), reusing the PBP-design classification rules |
| `game_date` | game date |
| `player_name` | source string verbatim |
| `franchise_id`, `opponent_franchise_id` | via the existing franchise alias mapping |
| `is_home` | from the source matchup designation |
| `min` | nullable int64; early-era quirks preserved, never zero-filled |
| `pts`, `fgm`, `fga`, `fg3m`, `fg3a`, `ftm`, `fta`, `oreb`, `dreb`, `reb`, `ast`, `stl`, `blk`, `tov`, `pf` | nullable int64 box line |
| `plus_minus` | nullable; sparse before 2007 — documented, not imputed |

### Validation gates (build fails loudly)

1. No duplicate `(game_id, person_id)` pairs.
2. Per team-game, player `pts` sums exactly to the published
   `team_games.pts` value — a full-coverage cross-check against the existing
   publication.
3. Per team-game, player `min` sums to `240 + 25 × overtime_periods` within
   a small documented rounding tolerance (source minutes are integers).
4. Every regular-season `game_id` exists in `games.parquet`; playoff and
   play-in coverage per season falls within known series bounds (PBP-design
   worklist rules reused).
5. A per-season coverage report (rows, players, gate results) is committed
   to `docs/audits/`.

### Stated limitation

Game logs contain only players who appeared. An **absence** is inferred: a
team game that falls inside a player's roster stint (between that player's
surrounding appearances for the franchise) with no appearance row. The
inference rule and its edge cases (stint boundaries, trades, ten-day
contracts) are implemented as regenerable code with tests, not stored data.
Per-game inactive lists are out of scope; `injury_events` is what explains
absences.

## D2 — `injury_events` (`data/parquet-large/injury_events/`)

### Fetcher (`src/nba_data/pst.py`)

Pro Sports Transactions basketball search, categories **Injuries**,
**Injured/Inactive List movement**, and **Personal reasons**, dates
1983-10-01 → present, paginated (~25 rows per page). Cached HTML +
sidecars under `data/raw/pst/`.
CLI: `python -m nba_data fetch-injuries [--start-date --end-date]` for
incremental refresh; default is the full window.

### Table

One row per source event.

| Column | Notes |
|---|---|
| `event_id` | deterministic hash of (event_date, raw player, raw team, notes, within-page ordinal) |
| `event_date`, `season` | source date; ending season by calendar mapping |
| `player_name_raw` | verbatim |
| `person_id` | nullable; resolved against `player_games` names active for that franchise-season; unresolved rows are kept and resolution coverage is reported |
| `franchise_id` | via the franchise alias mapping, extended as needed |
| `direction` | `out` or `returned` (PST relinquished/acquired columns) |
| `category` | which search category produced the row |
| `notes_raw` | verbatim |
| `event_class` | parsed beside raw: `injury`, `illness`, `rest`, `personal`, `other` — keyword classification, regenerable code |
| `body_part` | nullable, best-effort parse |

### Validation

Gates: event dates within plausible season calendars; every team string maps
to a franchise; no duplicate `event_id`; direction consistency (`returned`
generally follows an `out`) is *reported*, with violations preserved rather
than dropped.

**Coverage is documented, not gated.** PST is volunteer-compiled from media
reports and thins out before roughly 2000. The audit reports per-season
event counts, person-id resolution rates, and the explicit caveat that
absence-of-event ≠ absence-of-injury; any analysis built on this table must
carry that asymmetry into its design.

### Cross-validation with `player_games`

For sampled `out` events, the player should have no appearance rows in the
immediately following games; the audit reports the agreement rate. This
catches date-parsing and name-resolution errors and is the payoff of
building D1 and D2 in one workstream.

## D3 — Schedule features (`src/nba_data/features/schedule.py`)

Pure functions from `games.parquet` to per team-game features:
`rest_days`, `is_back_to_back`, `games_in_last_7`, `is_3_in_4`,
`road_trip_game_number`, `travel_km`, `tz_shift`. Never stored; regenerated
by code (repo rule).

- **Locations.** One committed reference table,
  `reference/franchise_locations.csv`
  (`franchise_id`, `first_season`, `last_season`, `lat`, `lon`, `timezone`,
  provenance note) — city-level precision, since `venues.parquet` covers
  only 2020–22 eras.
- **Neutral/bubble games** use the neutral venue's location via the existing
  `neutral_site` flags (Orlando bubble ⇒ zero travel between bubble games).
- **Season boundaries**: first game of a season has null `rest_days`, never
  a sentinel large number.

## Tests (pytest, fixtures)

- Player-log parser on a cached-season fixture fragment.
- Points-sum and minutes-sum gates fire on seeded bad input.
- Game-type classification from ID prefix, including unknown-prefix
  rejection (shared with the PBP work).
- PST parser on quirky fixture rows: multi-injury notes, returned-to-lineup
  phrasing, name variants (`DeAndre' Bembry`).
- `event_class` keyword classifier on labeled examples, including `rest`.
- Name → `person_id` resolution, including an ambiguous same-name case.
- Absence-inference rule on toy stints: mid-stint gap, trade boundary,
  ten-day contract.
- Schedule features on a toy schedule: back-to-back, 3-in-4, season
  boundary, bubble travel, road-trip counter.

## Out of scope

- The three analyses (rest → performance; schedule compression → injuries;
  load-management trends) — each gets its own design and plan.
- Official NBA injury-report PDFs (2019+) — future enrichment.
- Per-game inactive lists.
- Play-by-play-derived workload features (stints, high-usage minutes) —
  later work on top of the PBP archive.
- Any committed large Parquet.

## Success criteria

1. `player_games` covers every worklist game for 1984–2026 with gates
   green; the points-sum cross-check passes for every team-game.
2. `injury_events` builds with gates green; the committed audit documents
   per-season coverage, resolution rates, and the out-event vs. absence
   agreement check.
3. Schedule features regenerate deterministically from committed data plus
   reference tables, with tests covering the boundary cases above.
4. Raw caches and Parquet outputs are checksummed and NAS-mirrored; the
   fresh-clone <100 MB criterion is unaffected.
